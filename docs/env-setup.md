# API 키 관리 방법 (.env 설정)

## .env가 무엇이고 왜 필요한가

API 키는 "이 프로그램이 정부 API를 사용할 자격이 있다"는 것을 증명하는
비밀번호와 같다. 이 키가 유출되면 다른 사람이 내 키로 무제한 요청을
보내 사용량 제한에 걸리거나, 최악의 경우 악용될 수 있다.

`.env` 파일은 이런 비밀 값들을 코드와 분리해서 저장하는 파일이다.
비유하자면: 코드는 "출판되는 책"이고, `.env`는 "책상 서랍 속 개인 메모"다.
책(코드)은 나중에 깃허브에 올리거나 다른 사람과 공유할 수 있지만, 서랍
속 메모(.env)는 절대 공유하지 않는다.

## 이 프로젝트에 만들어진 파일

| 파일 | 용도 | 깃(Git)에 커밋됨? |
|---|---|---|
| `.env` | 실제 API 키 값이 들어가는 파일 | ❌ 절대 안 됨 (.gitignore가 막음) |
| `.env.example` | 어떤 키가 필요한지 보여주는 견본(값은 비어있음) | ✅ 됨 (안전함) |
| `.gitignore` | `.env`를 깃에 올리지 못하게 막는 설정 파일 | ✅ 됨 |

## API 키를 .env에 넣는 방법

1. 프로젝트 폴더의 `.env` 파일을 메모장 등으로 연다.
2. `BIZINFO_API_KEY=` 뒤에 발급받은 키 값을 붙여넣는다. (앞뒤 공백,
   따옴표 없이 값만 붙여넣는다)
   ```
   BIZINFO_API_KEY=여기에실제키값
   ```
   (이 문서는 예시 설명용 파일이다. 실제 키 값은 절대 이 문서에 적지 말고,
   `.env` 파일에만 입력한다. — 아래 "확인 결과" 참고)
3. 저장한다. 이게 전부다 — 이 파일은 깃에 올라가지 않으므로 안전하다.

## 지켜야 할 원칙

- `.env` 파일 내용을 카카오톡, 이메일, 채팅창(Claude 포함), 캡처화면 등
  어디에도 붙여넣지 않는다. 채팅에 붙여넣은 값은 대화 기록에 남을 수
  있으므로, 키는 항상 파일에 직접 입력하는 방식을 쓴다.
- 새로운 API(K-Startup, 공공데이터포털 등)를 추가할 때마다
  `.env.example`에 "이런 키가 필요하다"는 항목명만 추가하고, 실제 값은
  각자의 `.env`에만 넣는다.
- 만약 실수로 키가 깃허브 같은 공개된 곳에 올라갔다면, 그 즉시 해당
  기관의 API 관리 페이지에서 키를 재발급(기존 키 폐기)해야 한다.

## 공공데이터포털 키에 대한 참고

공공데이터포털(data.go.kr)에서 발급받는 서비스키는 보통 "Encoding"과
"Decoding" 두 형태로 제공된다. 코드에서 요청 URL을 직접 조립할 때는
Decoding 키를 쓰는 경우가 많다 — 실제 개발 단계에서 API 문서를 보며
어떤 키가 맞는지 다시 확인한다.

## 새 기관을 추가할 때 환경변수 등록 절차

1. `.env.example`에 새 줄을 추가한다 (값은 비워둠):
   ```
   KOSMES_API_KEY=
   ```
2. `.env`에도 같은 이름으로 줄을 추가한다. 키를 아직 발급받지 못했다면
   빈 채로 둬도 된다 — 코드가 "승인 대기 또는 키 미설정"으로 알아서
   표시한다 (`collector/adapters/base.py`의 `check_readiness()`).
3. `app/db/migrations/`의 `data_sources` 등록에 `env_var_name` 컬럼을
   같은 이름으로 맞춰 적는다 (자세한 절차는 `docs/adding-new-source.md`).

## 코드에서 실제로 사용하는 방식

이 프로젝트는 `python-dotenv` 같은 라이브러리를 쓰지 않고, `.env` 파일을
직접 읽는 작은 함수를 쓴다 (`collector/common/env.py`의
`load_env_file()`/`get_env_value()`). 모든 어댑터는 이 함수를 통해서만
키를 읽고, 값을 화면이나 로그에 출력하지 않는다. 코드 안에는 실제 키
값이 절대 직접 적히지 않는다 — 항상 "환경변수 이름"만 코드에 등장하고,
값은 실행하는 그 컴퓨터의 `.env` 파일에서만 읽어온다.
