## 발견된 문제 목록 (심각도순)

### 문제 1 — "지역" 필드에 기관명이 잘못 들어간 사례 (5건, 전체의 25%)
- **증상**: 지식재산처 소관 5개 공고의 "지역" 값이 `지식재산처`로 저장됨
  (지역이 아니라 기관명이 지역 자리에 들어감).
- **원인**: `collector/fetch_and_store.py`의 지역 추정 로직이 "제목에
  `[지역]` 접두사가 없으면 소관기관명(jrsdInsttNm)을 그대로 지역으로
  사용"하는 단순 fallback이라, 소관기관이 지역이 아닌 중앙기관인 경우를
  걸러내지 못함.
- **영향 화면**: 목록 카드의 "지역" 열, 상세화면의 "지역(추정)" 항목.
- **제안하는 수정 방법** (적용 안 함): 대한민국 광역시·도 17개 명칭
  화이트리스트를 만들어, `jrsdInsttNm`이 그 목록에 없으면 지역을
  `None`(확인 필요)으로 두도록 `region_guess` 계산 부분에 검증 단계만
  추가. `fetch_and_store.py`의 `map_item_to_program` 함수 내 몇 줄 수정으로
  가능하며, 전체 구조 변경은 필요 없음.

### 문제 2 — 서로 다른 7개 지자체가 "기초자치단체" 한 이름으로 병합됨 (10건, 50%)
- **증상**: 안산시·성남시·수원시·속초시·원주시·음성군·진천군의 공고
  10건이 모두 `organizations` 테이블의 "기초자치단체"라는 **하나의 행**에
  연결되어 있음.
- **원인**: 기업마당 API의 `excInsttNm` 필드 자체가 이 경우 실제 도시명이
  아니라 "기초자치단체"라는 일반 명사를 돌려줌. 로더가 이 값을 그대로
  기관명으로 저장함.
- **영향**: 향후 기관별/기관구조 화면을 만들면 "기초자치단체"를 클릭했을
  때 서로 무관한 7개 도시 공고가 한 기관인 것처럼 섞여 나옴 — 설계문서의
  "정확한 기관 계층" 원칙과 충돌.
- **제안하는 수정 방법** (적용 안 함, 논의 필요): 두 가지 대안이 있음.
  1) 공고 제목의 `[경기] 안산시 ...` 패턴에서 실제 지자체명을 추출해
     기관명으로 보정 (정확도는 제목 표기 방식에 의존적).
  2) `excInsttNm`이 "기초자치단체"처럼 특정 기관을 가리키지 않는 일반
     명사일 경우, `organizations`에 넣지 않고 `program_fields`에
     "확인 필요" 상태로만 남긴다 (더 보수적이고 안전한 방법).
  둘 다 코드 변경이 필요한 사안이라 지금은 적용하지 않았다.

### 문제 3 — "직접수행"이 기관명처럼 저장됨 (1건)
- **증상**: `excInsttNm` 값이 "직접수행"(소관기관이 직접 수행한다는
  뜻의 서술어)인데, 이것도 그대로 기관명으로 `organizations`에 저장됨.
- **제안**: 문제 2와 같은 방식(일반명사 화이트리스트/블랙리스트)으로
  함께 처리 가능. "기초자치단체", "직접수행" 등을 "기관명이 아닌 값"
  목록으로 관리.

### 문제 4 — 공고상태 "비정형(원문 참조)"가 실제 상태처럼 필터에 노출 (6건, 30%)
- **증상**: 신청기간이 "수시 접수" / "예산 소진시까지" / "회차별 상이"인
  6건은 공고상태가 `비정형(원문 참조)`로 계산되어, 목록 화면의 "공고상태"
  필터 드롭다운에 접수중·마감임박·마감과 나란히 노출됨.
- **문제점**: "비정형(원문 참조)"은 개발 과정에서 붙인 내부 용어라
  일반 사용자가 의미를 알기 어려움.
- **제안**: 화면에 보여줄 라벨만 예: "상시/조건부 접수(원문 확인 필요)"
  처럼 사용자 친화적으로 바꾸는 표시용 매핑을 추가. 저장된 값 자체를
  바꾸는 게 아니라 화면에 뿌릴 때만 변환하면 되므로 구조 변경은 아님.

### 문제 5 — "AI 분석" 배지가 실제로는 단순 날짜 계산에 붙어 있음
- **증상**: 공고상태의 확인상태가 `AI 분석`으로 표시되는데, 실제로는
  AI(LLM)가 아니라 파이썬 날짜 비교 규칙(`parse_application_period`)으로
  계산된 값. 사용자가 "AI가 실제로 분석했다"고 오해할 수 있음.
- **제안**: 이 값의 표시 라벨을 "AI 분석" 대신 "자동 계산"처럼 더 정확한
  용어로 바꿀 것을 제안. (장기적으로는 확인상태 체계에 "규칙기반 계산"
  이라는 4번째 값을 추가하는 것도 검토할 만하지만, 이는 스키마 변경이라
  별도 논의 후 결정 필요.)

### 문제 6 — 사용자에게 노출되면 안 되는 개발자 시점 문구 (3곳)
| 위치 | 현재 문구 | 문제 | 제안 문구(예시) |
|---|---|---|---|
| `detail.html` 상세 항목 제목 | "세부 항목 (**요청하신** 9개 항목)" | "요청하신"은 저(Claude)와 사용자님의 개발 대화에서 나온 표현이 그대로 화면에 남은 것. 실제 서비스 이용자는 아무것도 요청한 적이 없어 의미 불명 | "핵심 세부 항목" |
| `detail.html` 참고 정보 제목 | "참고 정보 (**실제 확보된** 원문 항목)" | 마찬가지로 내부 개발 맥락 표현 | "그 외 확인된 정보" |
| `detail.html` 상단 출처 표기 | "기업마당 (**source_item_id**: ...)" | 영문 내부 변수명이 그대로 노출됨 | "기업마당 공고번호: ..." |

### 문제 7 (경미) — "지역" 추정 여부 표시가 목록/상세 화면에서 다름
- 상세화면은 "지역(**추정**)"이라고 명시하지만, 목록 카드는 그냥
  "지역"이라고만 써서 추정값이라는 사실이 목록에서는 드러나지 않음.
- 제안: 목록 카드의 라벨도 "지역(추정)"으로 통일.

### 문제 8 (디자인, 경미) — "출처: 기업마당" 배지 색상이 "정보 없음" 배지와 동일
- `list.html`에서 "출처: 기업마당" 배지가 `badge-missing`(원래 '미추출'용
  회색) 스타일을 재사용 중이라, 정상적인 출처 표시인데도 시각적으로
  "정보 없음"류 배지처럼 보일 수 있음.
- 제안: 중립적인 별도 스타일(`badge-source`)로 분리.

## 점검했지만 문제 없었던 것 (참고)

- 사업명·주관기관·소관기관·신청기간 원문 — 20건 전부 비어있지 않음
- 원문 URL(20건)·첨부파일 URL(22건) — 전부 `https://www.bizinfo.go.kr/...` 형태의 정상 패턴, `pblancId` 포함 확인
- confirmation_status와 실제 값의 기계적 불일치(확인된 사실인데 빈 값, 미추출인데 값 있음 등) — 0건
- 지원금액은 20건 전부 정직하게 "미추출"로 표시됨. 다만 그중 6건은
  사업요약(`bsnsSumryCn`) 본문에 실제 금액이 텍스트로 포함되어 있음을
  확인함(예: "개소당 최대 8백만원") — 버그는 아니지만, 향후 텍스트
  추출을 붙이면 바로 이득을 볼 수 있는 지점으로 참고할 만함.
