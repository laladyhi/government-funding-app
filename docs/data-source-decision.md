# Phase 1 데이터 출처 확정

**결정일**: 2026-09-04
**결정**: 기업마당(bizinfo.go.kr) API를 Phase 1의 기본(유일한) 데이터
출처로 확정한다. 근거: [agency-coverage-survey.md](agency-coverage-survey.md)
(2026-09-04 조사) — 기업마당은 약 560여 개 참여기관의 정책정보를 모으는
허브이며, 조사한 6개 산하기관 모두 과거 게재 이력이 확인되어 Phase 1
범위에서는 기업마당 하나로 상당 부분을 커버할 수 있다고 판단했다.

## 화면·문서 표기 원칙

"모든 정부지원사업"처럼 완전성을 주장하는 표현을 화면과 문서 어디에도
쓰지 않는다. 대신 다음 4가지가 항상 함께 보이거나 확인 가능해야 한다.

| 원칙 | 반영 위치 |
|---|---|
| 기업마당에 연계된 지원사업이라는 점 | 모든 화면 상단 배너([app/templates/base.html](../app/templates/base.html)), 목록 화면 제목 |
| 기업마당 수집 기준일 | 상단 배너에 `raw_api_responses`의 최신 수집 시각을 자동 표시 ([app/server.py](../app/server.py)의 `inject_data_source_meta`) |
| 원문 출처 | 목록 카드의 출처 배지, 상세 화면 항목별 "원문 열기" 링크(사실 단위 출처, [phase1-data-model.md](phase1-data-model.md) 4번) |
| 기관별 공고 누락·반영 지연 가능성 | 상단 배너 문구("기업마당에 참여하지 않았거나 반영이 지연된 기관의 공고는 이 화면에 없을 수 있습니다") |

## 기관 등록 정책 (자동 수집 여부에 따른 3단계 구분)

`organizations.registration_status` 컬럼(마이그레이션
[0002_source_scope_and_org_links.sql](../app/db/migrations/0002_source_scope_and_org_links.sql))
으로 관리한다. 새로운 상태값이 필요하면 코드가 아니라 이 컬럼의
CHECK 제약과 데이터만 수정하면 된다.

| 상태값 | 의미 | 현재 해당 기관 |
|---|---|---|
| `기업마당경유` | 기업마당이 수집한 공고 안에서 기관명이 확인됨 — 현재 자동으로 화면에 반영됨 | 로컬 DB 표본에서 발견된 15개 기관(지자체·테크노파크 등) |
| `링크만관리` | 기업마당 게재 이력은 있으나 자체 API/RSS가 확인되지 않음 — **자동 수집하지 않고** 기관명·공식 홈페이지·공식 공고 페이지·출처만 등록 | 한국콘텐츠진흥원, 한국관광공사, 영화진흥위원회, 국민체육진흥공단 |
| `연동후보` | 자체 Open API 존재가 확인됨 — **아직 코드는 작성하지 않고** 다음 단계 연동 후보로만 기록 | 창업진흥원(K-Startup), 중소벤처기업진흥공단(KOSMES) |

`링크만관리`, `연동후보` 기관 모두 이번 결정에서 **어댑터/수집 코드를
작성하지 않았다** — DB에는 기관명, 공식 홈페이지(`homepage_url`), 공식
공고 페이지(`announcement_page_url`), 근거(`source_reference`), 참고
메모(`api_notes`)만 데이터로 등록되어 있다.

## 다음 단계로 미룬 것 (이번에 하지 않은 것)

- `링크만관리`/`연동후보` 기관에 대한 실제 수집기·크롤러·API 어댑터 개발
- 이 기관들을 화면(기관별/기관구조)에 노출하는 UI — 데이터는 등록됐지만
  아직 화면에서 보여주지는 않는다
- 기업마당 반영 비율(전체 대비 %)에 대한 정량적 확인 — API 재호출 없이는
  확인 불가
