# 실제 수집을 시작하기 전에 확인할 항목

이 문서는 어떤 기관이든 "픽스처 테스트 통과 → 실제 자동 수집 시작"으로
넘어가기 **직전**에 사람이 직접 확인해야 하는 체크리스트다. 아래 항목이
전부 확인되기 전에는 실제 수집을 자동화(스케줄링)하지 않는다.

## 1. 자격/법적 확인
- [ ] API 서비스키가 **운영단계 승인**을 받았는가 (개발단계 자동승인과는
      다름 — 운영단계는 별도 심의가 필요한 경우가 많다)
- [ ] 이용약관에 자동수집/크롤링을 금지하는 조항이 없는가
      (있다면 반드시 게시판 크롤링이 아니라 공식 API로만 접근)
- [ ] 데이터 재사용 라이선스(공공누리 등)를 확인했는가 — 화면에
      출처 표시가 필요한 경우 빠뜨리지 않았는가
- [ ] `robots.txt`를 확인했는가 (게시판을 직접 방문하는 방식일 경우)

## 2. 기술적 확인
- [ ] 실제 응답 1회 이상을 받아 `ASSUMED_FIELDS`(추정 필드명)를 실제
      필드명으로 교체했는가
- [ ] 페이지네이션 파라미터(페이지 크기, 페이지 번호, 전체 건수 필드)를
      실제로 확인했는가
- [ ] 첨부파일이 응답에 포함되는지, 포함된다면 URL 형태가 어떤지
      확인했는가
- [ ] 신청기간이 비정형 텍스트로 오는 경우가 있는지 실제 데이터로
      확인했는가 (있다면 날짜를 지어내지 않고 원문만 보존하는지 재확인)

## 3. 운영 준비
- [ ] 요청 간격(rate limit)을 지키도록 설정했는가 — 짧은 시간에 대량
      요청을 보내지 않는가
- [ ] 오류 발생 시 `log_error()`로 기록되고, 무한 재시도하지 않는가
- [ ] `data_sources.connection_status`를 `연결됨`으로 갱신했는가
- [ ] `data_sources.last_checked_at`을 오늘 날짜로 갱신했는가

## 4. 교차 출처 중복 확인
- [ ] 이미 다른 출처(예: 기업마당)에 같은 공고가 있을 가능성을 알고
      있는가 — `cross_source_duplicate_candidates` 표를 참고해 중복
      판별 기준(제목 유사도, 기관 일치, 기간 겹침 등)을 세웠는가
      (표 구조는 준비돼 있으나, 실제 판별 로직은 출처가 2개 이상 실제로
      연결된 뒤에 채우는 것을 권장한다)

## 5. 스케줄링(자동 반복 수집)을 켜기 전
- [ ] 사람이 명시적으로 "이제 자동 수집을 시작해줘"라고 요청했는가 —
      이 프로젝트는 지금까지 어떤 단계에서도 스케줄링을 자동으로 켠 적이
      없다. 위 1~4번이 전부 확인된 뒤에도, 스케줄링 자체는 별도 승인
      없이 시작하지 않는다.
